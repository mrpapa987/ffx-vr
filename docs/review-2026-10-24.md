# Code review, 24 Oct 2026

A peer-review pass over everything: the native DLL (three slices), ffxvr_xr, module.cs and
the PowerShell tools. Nothing here is implemented yet. Line numbers are as of commit 9a8715e.
"Checked" means confirmed by reading the code after the review; the rest are the reviewers'
findings, read but not re-traced line by line.

Effort: S = under an hour, M = a session, L = more.

## Tier 1: fix first (they affect play today)

| # | What | Where | Effort |
|---|---|---|---|
| R1 | **Settings only reach native while the F8 window is open.** `cuts_set` carries the frame time (`g_dt`), and it is only pushed from `draw_main`. With the overlay closed (the normal way to play) `g_dt` stays at the last value pushed, or the 1/72 default. Smooth stick turn, third-person follow, follow pans, seat pitch and auto-depth easing all run on a frozen timestep. The same applies to `xr_pitch_follow`, `backdrop_set`, `hist_set`, `ui_set`, and to `noimg_set`/`bisect_set` (Debug header). A collapsed window (Begin returns false) pushes *nothing*, including `push_player`, so the first-person camera stops following. **Checked.** | module.cs 1972-1994, 1020-1111; native 482, 5195 | S: one `push_all()` every frame, whatever the UI state; native measures its own dt with QPC in begin_frame |
| R2 | **A blocking GPU readback every frame.** `read_camera()` copies slot 0 to staging and maps it with flags 0 inside begin_frame, so the CPU waits for the GPU to finish the frame, every frame. The result only feeds a heartbeat diagnostic. Staging is also only recreated when it is too small, so a size change makes CopyResource fail silently. **Checked.** | native 3253-3301, 3525 | S: remove it, or gate it behind a debug flag with DO_NOT_WAIT |
| R3 | **Two full-resolution scene copies every stereo frame.** `snapshot_scene` copies the eye-2 twin and the game target (4K, maybe MSAA) every frame. They are only read by the overlay's eye preview, `measure` and the image dumps. **Checked.** | native 4141-4161, 4378 | S: only snapshot when a preview, measure or dump was requested recently; free them otherwise |
| R4 | **Camera smoothing runs per camera upload, not per frame.** `build_override_view` advances the third-person yaw slew, the diorama/battle anchor smoothing (k = 0.5 / 0.05 "per frame") and the seat follow on every call. It is called for every camera-carrying upload (many per frame), and again for the markers. So the rate limits are N times faster than intended, and within one frame early and late objects see different anchors (possible 30 Hz jitter and stereo mismatch in third person and diorama). **Checked.** The speeds were tuned by feel, so they need retuning after the fix. | native 1170-1182, 1208-1214, 1247-1256, called from 1402 and 5051 | M: advance the filters once per frame (like `g_s3_frame` for auto depth) and make the view builder read-only |
| R5 | **build-mod deletes your captures.** The keep list has no `*.bmp` or `*.dds`, so every build wipes `img_*.bmp`, `seq_*.bmp` and `ui_atlas_*.dds` from the mod folder. That is why image captures never reached me. run-ffx also never collects `.dds`. **Checked.** | tools/build-mod.ps1 ~191, run-ffx.ps1 52 | S |
| R6 | **Turning the headset off leaves VR-only flags set.** `g_ovr_suspend`, `g_screen3d_now`, `g_xr_screen_now`, `g_backdrop_room` and `g_ui_state` are only updated inside `xr_tick`, which returns at once when the headset is off. Turn it off during a menu/FMV and the desktop override stays suspended. Turn it off in stereo-screen mode and desktop eye 2 keeps the screen-3D path and first-person body hiding stays off. | native 5377, 5399, 5453-5460, 2729 | S: a `leave_xr()` reset, called from all three exits |
| R7 | **Render-thread file I/O and retries.** (a) With autostart on and Virtual Desktop not connected, `ffxvr_xr_set(1)` retries `xr_start` every frame: loader instance create/destroy plus 2-3 log lines each time. (b) `fail()` in ffxvr_xr logs every frame while an XR call keeps failing. (c) The heartbeat opens two log files once a second, holding the mutex while it prints every tracked buffer. (d) `tick()` (GetAsyncKeyState) runs on every Unmap, hundreds per frame. Together these give stutter and fast-growing logs. | native 5183-5189, 2896-3000, 3221; xr 254-258 | S: back off xr_start (2-5 s), log on change only, heartbeat behind a toggle, tick once per frame |
| R8 | **Swapchain wait timeout is handled against the spec.** After `XR_TIMEOUT_EXPIRED` the code releases an image it never waited on. The release fails and the image stays acquired, so that layer shows the previous frame from then on. After a few timeouts acquire fails for good and the layer (an eye, the screen or the UI) goes dead until restart. Most likely during Virtual Desktop hiccups. | xr 471-475 | S: remember "acquired, not waited" and retry the wait next frame |

## Tier 2: latent crashes (haven't bitten yet)

| # | What | Where | Effort |
|---|---|---|---|
| R9 | **Stale UI vertex pointers.** `g_vb_last_map` keeps the last Map pointer of every buffer forever. `VbMap.frame` is stored but never checked (design-notes says "last two frames"), and nothing is pruned. After an area change a freed buffer address can be reused, and the reader follows a dead mapping. The SEH guard doesn't save us under Fahrenheit's debugger (exe-analysis §2). | native 1996-1998, 2066, 2110, 3186 | S: reject entries older than 2 frames, prune in sweep_caches |
| R10 | **Stack overflow in the F9 pick.** `guarded_read_xy` always writes 8 floats, but the pick passes `float v[4]` / `v2[4]`. It also reads past the bounds check. **Checked.** | native 2073-2074, 2091 | S |
| R11 | **Raw tracked D3D views.** `g_cur_ps_srv`, `g_cur_rtv`, `g_cur_dsv` and `g_backbuffer` are pointers we never AddRef. D3D unbinds SRVs on its own (hazard tracking), Virtual Desktop binds views inside xrEndFrame, and ClearState isn't hooked. A view the game has since released then gets used: eye2_begin's `twin_srv`, eye2_end's restore of all 16 slots, the UI paths' `texture_of`. Also `g_backbuffer->GetDesc` runs for post-processing draws in the first frame after a resize. | native 1781-1791, 4263-4266, 4323, 4336, 3875 | M: read the real bindings with PSGet/OMGet (they come AddRef'd) where it matters; keep the backbuffer's size and format instead of the pointer |
| R12 | **twin_srv cache eviction mid-draw.** At 256 entries the cache releases all twin SRVs inside eye2_begin's slot loop, which can free one already placed in an earlier slot of the same bind. Failed twins are cached as empty and never retried. `fail()` leaks the RTV. A missing depth twin binds eye 2 with no depth buffer. | native 4119-4121, 4238-4244, 4058-4094 | S-M |
| R13 | **Missing native export means a null call.** GetExport throws at the first missing name, but the pointers already loaded stay set, hooks still install, and some call sites don't null-check (`_fn_patch_name`, `_fn_eye2_begin/end`, `_fn_xr_recenter`). A DLL mismatch then crashes the game instead of showing an error. | module.cs 320-448, 560/605, 977, 1215 | S: all-or-nothing load; TryGetExport for optional ones |
| R14 | **Stale fields in reused ring slots.** Backdrop and product-only uploads don't reset `split` / `pal_hands`. A stale `split` gives 3 passes and an UpdateSubresource from a wrongly sized `eye1b`, which is a heap over-read. Only reachable after the hands split mode was used. | native 2711-2715, 2781-2785 | S: one slot-reset helper |
| R15 | **No image means no xr_frame.** When the eye copy can't be made, `xr_tick` returns before `xr_frame`. Events aren't polled (no STOPPING/EXITING handling), the frame isn't ended, and the runtime sees a hung app. | native 5420 | S: always run xr_frame; submit zero layers when there is no image |
| R16 | **Hook install hygiene.** `patch()` would record our own hook as the "original" if run twice. A failed init doesn't roll back. Vtable patches are never undone. The CreateBuffer/CreateTexture2D hooks act on every device in the process, not just the game's (the MSAA override could touch the runtime's targets). | native 3303-3357, 3105-3141 | S |

## Tier 3: performance

Each item is a modest gain; together they're meaningful, and blitzball (30 fps, GPU ~19-20 ms) needs every ms.

| # | What | Where |
|---|---|---|
| R17 | Per draw, managed makes three native calls (`draw_ctx` and `draw_args` are diagnostic counters) plus a marshalled delegate for the original. Fold them into one call, `SuppressGCTransition` on the trivial exports, unmanaged function pointer for the chain. | module.cs 548-607 |
| R18 | `texture_of` (GetResource + QueryInterface + 2 Release) runs 10-15 times per eye-2 draw, plus map lookups and GetDesc. Resolve the texture and twin once at bind time; skip the 16-slot SRV restore when nothing was swapped. | native 4025-4034, on_draw, eye2_begin/end |
| R19 | Every constant-buffer write is copied (up to 64 KB) into `g_buffers`, including reads from write-combined mapped memory, the kind that froze battles before. Only diagnostics read it. Copy the data only while a census, pick or capture is armed. | native 2839-2845, 3197-3204 |
| R20 | The camera scan in `maybe_override` memcpys every unrecognised buffer of 64 bytes or more and runs an O(n²) compare, recomputing a per-frame scale on each call. Compute the scale once per frame, reject early, remember sizes that never matched. | native 1503-1535 |
| R21 | `settings_save_if_changed` rebuilds about 90 lines of ini text every frame (garbage, so GC pauses) and writes synchronously on every frame of a slider drag. Use a dirty flag and a 1 s debounce. | module.cs 862-952 |
| R22 | `actor_name()` allocates and does one VirtualQuery syscall per byte. When `c101` isn't there (cutscenes, battles) it scans all 48 actors every frame. Use one 16-byte read and cache "not found" until the map changes. Also: the pick result string, `map_base(...).StartsWith`, and `parse_mask` are rebuilt every frame. | module.cs 1779-1784, 1536-1541, 1969, 1810 |
| R23 | Eye 2 re-renders view-independent passes such as the shadow map (`stereo_scope` 0 = everything). Skip targets that took no eye-image draws. | native 3941-3946 |
| R24 | With no physical pad (headset-only players), the right-stick code polls XInput on all 4 slots every 2 s from the render thread. Empty slots are slow, so this is a periodic spike. Reuse the state the hooked import already got. | native 1103-1129 |
| R25 | XR: every layer is copied twice (shader into `mid`, then CopyResource), and six swapchains (four 2560x1440 quads, each with a `mid`) are created up front, ~200 MB VRAM even when unused. Render straight into swapchain images; create the screen-right/ImGui swapchains on first use. | xr 80-81, 401, 477 |
| R26 | Smaller ones: backdrop camera O(nb²) matrix products per upload (2252-2268); `bones_record` palette work with hands off (2561-2573); double QueryInterface/GetDesc in `as_constant_buffer`/`as_geometry_buffer`, plus a mutex and set lookup on every Map once picks were used (221-254). | native |

## Tier 4: settings file robustness

| # | What | Where |
|---|---|---|
| R27 | A bad or empty value becomes 0 (`TryParse` writes 0 on failure), and nothing is clamped. `world_scale=0` divides by zero in the gesture code; `battle_view` 0 puts every battle in the seat view. Parse into a temp, keep the default on failure, clamp to the slider range. | module.cs 744-827 |
| R28 | Live reload in first/third person loads `world_scale` straight into the current scale, so editing *any* key while in first person drops the world to tabletop size. The autostart block also re-runs on reload. | module.cs 830-856 |

| R31 | `headset_autostart=0` edited on disk is immediately reverted. The reload `Thread.Sleep` retries can freeze the render thread up to 1 s. If the read fails, the mtime is marked as seen and the edit is lost. | module.cs 849-857, 730-734 |

## Cursor art: the experiment was never really run

Two findings reopen the "reuse the game's cursor art" result, without changing the decision to keep the triangles:

- R43: `ptr_sprites_release()` runs in begin_frame *before* `xr_tick` draws the markers, so the captured sprites were always gone when the drawing code looked for them. "Nothing drawn" was this bug, not unknown UVs. **Checked.**
- R44: `quad_is_pointer` returns an index into the *projected* actor list, which `ptr_sprite_capture` uses as an index into the *live* list. These differ as soon as one actor is off screen, so the art would attach to the wrong actor.
- The native default for `g_ptr_reuse` is true while the managed default is off. Harmless today, but make them agree.

## VR hands (tabled; for when it comes back)

- R45: in the split path, eye 2's hand variant is copied before eye 2's camera is written, so it uploads the game's camera. This is a likely cause of "pass 2 is not landing" in the design notes.
- R46: `e.eye1` is snapshotted before the hand deltas are applied.
- R47: the world-matrix offset is +624 in one place and +640 in two others.
- R48: rect/pick readers ignore the draw's base vertex/start index; the capture and census honour them.

## Checked and fine

- Every C# `delegate* unmanaged[Cdecl]` matches its C export (136 of them), and the output buffer sizes match the native limits.
- The `g_mutex` discipline in the hot paths holds (no relock from `write_camera`/`frame_dump`).
- The auto-depth divisions are guarded, as are the FOV validation, the layer-count bounds, and the state save/restore in the copy and marker passes.
- Only one extra native thread exists (the XR watchdog), and it only reads.

## Suggested order

1. R1, R2, R3, R5, R7: small, and you'd feel them (turn speed and follow with the overlay closed, frame time, captures that survive a build).
2. R4: needs a test session to retune follow speeds.
3. R6, R8, R9-R16: crash-proofing before testers.
4. Tier 3 when chasing blitzball frame rate; R27-R33 before testers edit inis.
5. Scripts S1-S3 before the zip goes out; the rest when convenient.
